# `assets/badges/` — the approved badge masters

Source art for the 22 patches in `lib/badges/catalog.ts`. **Nothing here is generated by the
build and nothing here is edited in place.** See `docs/plans/F10-badge-art-skill.md`.

```
<key>.png       the approved 1024² master, promoted by hand from a candidate
<key>.txt       its sidecar — the exact prompt, model, seed and style version it came from
_anchor.png     a byte-identical copy of whichever master was approved FIRST
_candidates/    every attempt, with its prompt beside it. gitignored.
```

## The three human acts

The `generate-badge` skill writes to `_candidates/` and stops. Everything below is a decision,
and none of it is undone by re-running a script.

**Promote** a candidate, both files, always — `make_badge_assets.py` reads the style version out
of the sidecar rather than out of `style.md`, so that a mixed deck is detectable:

```bash
cp assets/badges/_candidates/<key>.aNN.png assets/badges/<key>.png
cp assets/badges/_candidates/<key>.aNN.txt assets/badges/<key>.txt
```

**Set the anchor**, once, from whichever badge is approved first. Every subsequent generation
passes `--reference assets/badges/_anchor.png`, because 22 badges must share one twill tone, one
merrowed-border weight, one satin-stitch gauge and one raking-light direction — and every one of
those is a continuous quantity a text prompt specifies loosely and an image specifies exactly:

```bash
cp assets/badges/<first-approved>.png assets/badges/_anchor.png
```

**Ship it**, in its own commit, once all 22 are promoted. This regenerates `public/badges/**` and
`lib/badges/badge-art.ts` — it changes what the app serves, which is why it is never run from
inside the art-generation loop:

```bash
python3 tools/make_badge_assets.py
npm run badges:check && npm run typecheck
```

## Why the masters are committed and the derivatives are too

D12: badge art is generated offline and committed; there is no runtime image generation, at
~$0.04 and 4–5 minutes per image. The 1024² masters are the archival copy — they are what
`badges:check` recomputes every shipped filename's SHA-256 against, and what a future style
revision is diffed from. The WebP derivatives under `public/badges/` are content-hashed, which
is the only reason `next.config.ts` may serve them `immutable`.
