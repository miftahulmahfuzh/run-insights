## Context & Motivation
The coordinator's fan-out assigned this worker the API-route test-coverage idea with a specific list: upload, cron/nina, cron/rollup, admin/nina/upload. The framing was "app/ has 0 tests for 39 source files despite containing real request-handling business logic" — and the premise was *directionally* true (39 source files, 0 co-located tests) but wrong on its named candidates: a route handler that imports and drives the handler directly is behaviorally tested no matter where the test file lives. The first act of the session was therefore a coverage census of `app/api/` against the existing `tests/` corpus, which moved the actual gap to the five handlers listed above.

Why the remaining gap was real rather than bookkeeping: the two upload routes sit at the security perimeter. `app/api/upload/route.ts` constructs client-upload tokens — its pathname regex is the *only* thing standing between a request body and a blob-store path, and its owner-binding is the only thing keeping one user out of another's nina-chat folder. `app/api/admin/nina/upload/route.ts` gates admin-only minting with per-kind ceilings and a JPEG-only rule. The extract routes own the ingest pipeline's front door. None of this logic had ever been executed by the test suite — the repo's 5,000+ tests exercised the libs beneath them, but the handlers themselves ran only in production.

## Code / Design Details
The `handleUpload` fake is the pattern worth lifting for any future route-handler suite. The real SDK function mints a token; the only part the handler's logic touches is the callback it passes in, so the fake hands that callback to the test instead of implementing token minting:

```ts
// The fake captures the handler's own callback; tests drive it with the REAL signature
// (three args — clientPayload, { pathname, ... }, multipart) that tsc enforces.
vi.mock('@vercel/blob/client', () => ({
  handleUpload: vi.fn(async (_body, opts) => {
    captured.onBeforeGenerateToken = opts.onBeforeGenerateToken
    return { type: 'client upload', token: 'fake' }
  }),
}))
```

Two consequences follow from leaving the pathname predicates real. First, every accepted pathname in a test has passed the production regex, not a test-local copy of it — the shots branch's acceptance tests are impossible to fake green. Second, the refusal tests (prefix, extension, id length, `..` traversal, the admin route's three shapes) document the regex's *behavior*, and a mutation flip confirms the tests read the real thing.

The `[id]` suite's ownership test asserts the **cost property**, not just a status code: the 404 for a well-formed id you don't own must be *indistinguishable* from the 404 for a missing id — same status, same body shape — because a distinguishable response is an existence oracle. Both tests call the same assertion helper so the indistinguishability is enforced mechanically, not by two copies of a similar expectation that could drift apart.

Health's dead-DB test fires the `neon()` mock into a rejection and asserts the handler returns an honest 500 *carrying the error message* — the route's explicit contract is that a broken database is reported as a broken database, so the test fails if a future edit starts swallowing the message into a generic body, and the mutation flip (500→200) confirmed the test watches the status line too.

## Decisions & Trade-offs
- **Scope correction over assigned scope.** The idea named four routes; two were already tested. Writing them again would have inflated the suite with duplicate contracts that future maintainers would have to keep in sync with the existing cron suites. The honest move was to re-derive the gap from the tree and cover the five real ones — recorded here so the coordinator sees the deviation from the assignment and why.
- **Imported constants over literals in cap assertions.** Asserting `8 * 1024 * 1024` against the imported `ADMIN_AVATAR_MAX_UPLOAD_BYTES` makes the test tautological on the *number* but meaningful on the *wiring* — that the route consults this constant for this shape. A literal would additionally catch a retune, but would break on every legitimate retune and train people to update tests reflexively. Wiring is the contract; the number is policy.
- **Mock auth wholesale, keep predicates real.** The `@/auth` graph is heavy and irrelevant to handler logic; the pathname regexes are the handler logic. The split follows load-bearing-ness, not convenience.
- **`auth/[...nextauth]/route.ts` left untested by design.** It is a pure NextAuth passthrough containing none of our logic — a test would pin the library against itself. This is written down so the next "app/ has untested files" survey doesn't re-flag it.
- **Characterization over specification.** These tests describe what the handlers do today (including the 202-vs-200 asymmetry and the rethrow behavior), not what a redesign might prefer. The mutation pass is what keeps that honest: each test exists because it catches a real flip, so the suite measures behavior rather than echoing implementation.

## Follow-ups & YAGNI notes
- `app/api/auth/[...nextauth]/route.ts` remains untested **by design** — pure passthrough, zero logic of ours. Do not add it to a coverage survey's red column.
- If a new route handler is ever added, the co-located pattern is established and sanctioned by the vitest include; the two upload-handshake suites are the templates (gate-ordering first, then shape/cap table, then mislabel/foreign-owner refusals, then the 400 mapping).
- The mock's `unauthorizedJson`/`forbiddenJson` outputs must stay **byte-identical to the real helpers** in `lib/auth/requireUserId.ts` if those ever change — the test headers say so inline. A drift there makes the suites pass against a response shape production no longer sends.
- `onUploadCompleted` hooks are inert-by-design (production-only observability) and deliberately untested; a future observability session should decide whether they graduate to testable first.
- The cron suites' pre-existence suggests a small doc debt elsewhere: any coverage inventory that counts *files under a directory* rather than *symbols imported from it* will keep misreporting `app/api` gaps and non-gaps. The census table in this doc is the corrected baseline.
