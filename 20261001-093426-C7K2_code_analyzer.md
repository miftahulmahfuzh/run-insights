## Detailed Requirements Understanding

**Problem/Requirement Statement**

`/nina`'s full-screen photograph overlay is bubble-scoped. `components/nina/usePhotoViewer.ts` holds
`{ messageId, index }` and derives its photo list with `chatViewerPhotos(viewerMessage)` — *one*
message's `imageUrls`. `NINA_MAX_CHAT_IMAGES` is 3 plus at most one re-attached photo, so the overlay
pages across 1–4 photos and then wraps back onto itself. `components/nina/ChatImages.tsx`'s header
states this as a deliberate F35-phase-9 decision and points the conversation-wide case at
`/nina/about`'s Media section. **R1 overturns that decision for the chat surface**: the overlay must
page across every photograph rendered in the open conversation, in chronological order.

Paging across the session makes the overlay's position and the conversation's scroll position
disagree — the runner swipes to a photo from thirty bubbles ago, closes, and is still looking at the
bottom of the chat. **R2 is the fix**: while the overlay is open, the document scrolls to the bubble
that owns the photo on screen, so closing needs no special case at all.

**Success Criteria**

1. Tapping any photo in any bubble opens the overlay at that photo, and the overlay's counter reads
   `<position in session> / <total photos in session>`.
2. A left swipe (or `ArrowRight`, or a dot) advances to the chronologically next photograph in the
   session, crossing bubble boundaries; a right swipe goes back; both wrap at the ends, exactly as
   `stepIndex` already defines.
3. The per-photo header name (`Foto kamu` / `Foto Nina`), the job-detail `headerAction`, the download
   and the attach control all act on the photo **currently on screen**, including after the overlay
   has crossed into a different bubble.
4. Changing the photo on screen to one owned by a *different* message scrolls the conversation
   behind the overlay to that message, instantly. Closing the overlay therefore lands on that bubble
   with no further work.
5. The overlay still survives its list changing underneath it (a `router.refresh()` from a service
   worker push, R8's delete) without `PhotoViewer`'s `photos[index]!` ever reading `undefined`.
6. The three review surfaces, `PhotoInclusionList`, `ErrorLogList`, `PhotoDeepLinkScreen` and
   `NinaAboutScreen` keep the overlay behaviour they have today.

**Key Considerations**

- **Scope of "that chat session" is the rendered window.** `app/nina/page.tsx:113` caps the screen at
  `CHAT_HISTORY_LIMIT = 200` messages of the active session. Photos older than that window are not in
  the DOM, have no `nina-msg-` anchor to scroll to, and are not in `messages`. The honest reading of
  R1 is therefore "every photo the open conversation is showing", and it is also the only reading R2
  can satisfy — a bubble outside the window cannot be scrolled to.
- **The dot row does not survive the widening.** `PhotoViewer` renders one dot per photo whenever
  `photos.length > 1`. At 1–4 photos that is a pager; at a session's worth it is a row of dozens of
  2 px slivers in a `flex` with no `wrap`. The header already carries `index + 1 / photos.length`.
- **The overlay's identity must stay a message id, not a flat index.** `usePhotoViewer`'s header
  records the reason at length: `messages` changes under an open overlay, and a stored snapshot (or a
  stored flat position) would silently re-aim at a different photograph when a row vanishes.
- **`PhotoViewer` locks `document.body.style.overflow`** while mounted. Per CSS Overflow, `hidden` is
  "scrollable, but no scrolling UI" — programmatic `window.scrollTo` still applies — so R2's scroll
  works behind the overlay. It is `clip` that would forbid it, and nothing here sets that.
- **The scroll arithmetic already exists and must not be re-invented.** `planQuoteScroll`
  (`lib/nina/reply.ts:439`) plus `measureQuoteScroll` (`components/nina/useQuoteLanding.ts`) is the
  one function that decides where a named bubble has to sit so the composer does not cover it. R12's
  quote tap, R1's `?jump=` mount landing and R1's soft-nav landing all route through it on purpose.
- **Invariant: the LLM's private image prose never reaches a component.** `ChatViewerPhoto` has no
  caption field and must not grow one (`tests/nina.chatPhoto.test.ts` asserts it structurally).
- **`ChatImages` / `MessageList`'s `onOpenImage(messageId, index)` contract is bubble-local and
  stays that way.** `tests/nina.chatPhoto.test.ts:36` pins the literal `onOpenImage(message.id, index)`
  in `MessageList`'s source. The widening belongs on the hook's side of that call, not on the grid's.

## Current Dataflow

### Entry Point: a tap on a photograph inside a chat bubble

**Location:** `components/nina/ChatImages.tsx` — the `<button>` branch, rendered only when `onOpen` is passed
**Trigger:** `onClick={() => onOpen(i)}`, where `i` indexes **this bubble's** `urls`
**Input Schema:** `i: number`
**Validation:** none — `i` is an array index the component itself produced
**Next Step:** `MessageList.tsx:200` closes over the row: `(index) => onOpenImage(message.id, index)`

### Processing Chain

1. **Function:** `MessageList`'s `onOpenImage` prop
   - **Location:** `components/nina/MessageList.tsx:108` (declaration), `:194-202` (call site)
   - **Input:** `(messageId: string, index: number)` — index is **bubble-local**
   - **Output:** calls `ChatScreen`'s `handleOpenImage`
   - **Note:** `onOpen` is passed only when `onOpenImage != null`, which is `ChatImages`'s
     "an absent `onOpen` means the grid is not interactive" contract.

2. **Function:** `handleOpenImage`
   - **Location:** `components/nina/ChatScreen.tsx:483-488`
   - **Transform:** `setNotice(null)` then `openViewer(messageId, index)`
   - **Calls:** `usePhotoViewer`'s `openViewer`

3. **Function:** `openViewer`
   - **Location:** `components/nina/usePhotoViewer.ts`
   - **Transform:** `setViewer({ messageId, index })`
   - **State:** `viewer: { messageId: string; index: number } | null` — **the overlay's whole identity**

4. **Derivation (every render):** `usePhotoViewer`
   - `viewerMessage = messages.find(c => c.id === viewer.messageId) ?? null`
   - `viewerPhotos = useMemo(() => chatViewerPhotos(viewerMessage), [viewerMessage])`
     — **one message's photos**
   - `shownIndex = viewerIndex(viewer.index, viewerPhotos.length)` — clamps, or `null`
   - `if (viewer !== null && shownIndex === null) setViewer(null)` — a **during-render** close, chosen
     over an effect because `react-hooks/set-state-in-effect` rejects the effect form
   - `viewerAttachId = attachableIdAt(viewerMessage?.imageIds, shownIndex)` — indexes the **message's**
     parallel `imageIds` array with the **bubble-local** index

5. **Function:** `chatViewerPhotos`
   - **Location:** `lib/nina/chatphotos.ts`
   - **Input:** `{ imageUrls?, imageKinds?, turnId? } | null`
   - **Transform:** per url → `{ url, kind: kinds?.[i] ?? 'upload', label: NINA_SIDE_LABEL[photoSideOf(kind)], id: kind === 'generated' && turnId ? turnId : undefined }`
   - **Output:** `ChatViewerPhoto[]` — structurally assignable to `readonly ViewerPhoto[]`
   - **Invariant:** no caption field, ever (invariant 5)

6. **Render:** `ChatScreen.tsx:615-694`
   - `<PhotoViewer photos={viewerPhotos} index={shownIndex} onIndex={(next) => setViewerIndex(viewer.messageId, next)} … />`
   - `onIndex` **re-aims at the same message** — this line is the whole of the bubble-scoping
   - `actions={<ChatPhotoActions url={viewerPhotos[shownIndex]!.url} label={…} onAttach={viewerAttachId === null ? null : () => setPhoto({ kind: 'image', id: viewerAttachId, url: … })} />}`
   - `headerAction={(photo) => photo.id == null ? null : <Link href={ninaJobHref(photo.id)} …>}`

7. **Component:** `PhotoViewer`
   - **Location:** `components/ui/PhotoViewer.tsx`
   - `page(delta) = onIndex(stepIndex(index, delta, photos.length))` — the single paging path
   - Keyboard: `Escape` → `onClose`, `ArrowRight` → `page(1)`, `ArrowLeft` → `page(-1)`
   - Touch: `onTouchStart/Move/End` collect a `SwipeGesture`; `decideSwipe` returns `'next' | 'prev' | 'none'`
   - **Side effect:** `document.body.style.overflow = 'hidden'` for the lifetime of the overlay,
     restored on unmount
   - **Side effect:** on every `index` change, `panRef.current?.scrollTo({ top: 0, left: 0 })`
   - Header: `nameOf(photo)`, optional `photo.meta`, and `index + 1 / photos.length` when `length > 1`
   - Footer: **one dot per photo** when `photos.length > 1`, each `aria-label={\`Show the ${nameOf(p)} ${subject}\`}`

### The conversation's own scroll (R2's neighbourhood)

- **`components/nina/useChatPageScroll.ts`** — samples `isNearBottom` on a passive `scroll` listener
