## Detailed Requirements Understanding

**Requirement statement.** Add a first-class conversational surface to Run Insights, owned by a
character called Nina, whose defining property is that she speaks first. She reads the entire
database as context, remembers what the runner tells her about himself forever, holds opinions
about his training, sees photographs, makes photographs, and occasionally shouts. Mechanically
this is: eight new tables, a new `lib/nina/` module tree with its own facts boundary and its own
agentic turn loop over `glm-5.3`, a fifth tab and a chat screen, a `glm-4.6v` vision pre-pass, a
runtime OpenRouter image path, a proactivity engine on cron plus `after()`, Web Push with a
service worker this app does not yet have, and a local operator skill.

**Success criteria.**

- Nina answers in the runner's language, in Jakarta register when that language is Indonesian, in
  one to four short bubbles that arrive staggered.
- She never states a number the app did not compute. Every metric in her mouth came from a
  precomputed field.
- She initiates. Four triggers fire without the runner opening the app: a committed run, a missed
  usual day, a crossed pattern threshold, prolonged silence.
- She remembers. A fact stated once is available months later, and the structured half of that
  memory is queryable by a cron job.
- She sees an uploaded photo and reacts to what is actually in it.
- She generates her own photographs, on request and on a promise coming due, with her face intact.
- **A failed generation always ends in a message, never in a spinner.** Every generation job has a
  hard deadline and a terminal failure state, and reaching either makes Nina say so in her own
  voice — "sori, kamera gw ngadat" — with no error code, no retry button, and no stack trace.
  This deliberately **inverts** `lib/llm/narrate.ts`'s rule that "the only safe fallback for prose
  is the absence of prose". That rule is right for a coaching narrative, where a canned platitude
  would fake a fact. It is wrong here: the runner asked a friend for a photo and a friend who goes
  quiet is the failure. Do not "restore consistency" by deleting the apology.
- `npm run typecheck && npm run lint && npm test` and every `ci:*` guard pass at the end of each
  phase.

**Key considerations.**

- **The arithmetic prohibition is not negotiable and is not a style rule.** `lib/llm/facts.ts`
  records a measurement: asked to compute aerobic decoupling from raw splits, `glm-5.3` returned
  −14.1% against a true +12.3%. A flipped sign. Nina's context builder inherits this rule
  wholesale — R15's "compare two runs" is therefore a *precomputed comparison* served by a tool,
  never two run objects and an instruction to subtract.
- **`glm-5.3` cannot see.** `lib/env.ts` and `lib/llm/vision.ts` both record that the
  Anthropic-shaped z.ai endpoint accepts an image block, answers HTTP 200, silently drops the
  image, reports 141 prompt tokens for the whole request, and invents plausible numbers. R10 is
  therefore a two-model path, not a parameter.
- **Vitest runs `environment: 'node'` with no jsdom.** Every piece of chat behaviour that deserves
  a test — bubble reveal timing, scroll-anchor arithmetic, reply-quote resolution, swipe gating —
  must be extracted into a pure function, exactly as `lib/photos/gallery.ts` was extracted from
  `components/ui/PhotoViewer.tsx`. This is a hard constraint on how phases 4, 7, 8 and 13 are
  written, not a preference.
- **Three invariants are being repealed, and repeal is a code change with a paper trail.** Each
  one is a documented decision with a CI guard behind it. The guards get edited to state the new
  rule and cite the ruling that changed it; none is deleted outright and none is silenced.
- **`profiles` has no gender column.** R6 names gender explicitly and the schema has never had it.
- **A conditional promise is a fourth kind of memory.** R19 requires storing "if X happens, do Y"
  and evaluating it later against reality. It rides in the slot table as `pending_promises`.
- **Single user, no privacy constraints.** Stated explicitly. Ownership scoping stays because the
  query layer is built that way and fighting it costs more than keeping it.

## Current Dataflow

### Entry Point: `POST /api/upload` → `POST /api/extract` → review → commit

**Location:** `app/api/upload/route.ts`, `app/api/extract/route.ts`, `lib/review/commit.ts`
**Trigger:** the runner picks screenshots on `/upload`.

The route never receives image bytes — it mints a short-lived signed Blob token and the browser
PUTs directly, because a Vercel Function rejects bodies over ~4.5 MB and streaming an upload
through a function bills wall-clock for nothing. `POST /api/extract` then creates the
`extractions` row, and a background job calls `glm-4.6v` through `lib/llm/vision.ts`.

**The token-floor guard** (`TOKEN_FLOOR_PER_IMAGE = 500`, multiplied by image count) is the
highest-value code in the repository: it is the only signal that the endpoint dropped an image,
because the API reports success either way.

`lib/review/commit.ts` is where a `runs` row is INSERTed, `reviewed_at` is stamped, records are
recomputed and badges are evaluated. **This is the attachment point for R8** — a committed run is
the event Nina reacts to, and `after()` is how she reacts without delaying the redirect.

### Entry Point: `ensureRunInsight` Server Action (`lib/insights/actions.ts`)

**Trigger:** a client effect in `components/insights/InsightTrigger.tsx`, after the run detail
page has already rendered its numbers.

**The boundary that matters:** a cache miss is a 10–35 s model call, so no render path may await
it. `scripts/check-llm-payload-boundary.mjs` rule 2 greps `app/`, `lib/` and `components/` for
`getOrCreateInsight(` and fails on any caller outside three sanctioned files. **Nina's turn action
inherits this rule** and the guard gains a second symbol.

**Data transformation:** `loadSessionFacts` fetches rows; `lib/llm/facts.ts` builds a
`SessionFacts` object field by field. Every string is produced by `lib/format.ts` — the same
`formatPace(442, true)` the run detail page calls — so the model reads the exact characters the
runner reads. `NarrativeProfile` is a deliberate two-field type (`birthYear`, `heightCm`) so that
passing F03's full `Profile` is a compile error rather than a code-review catch.

### Entry Point: `narrate.ts` → `glm-5.3`

**Location:** `lib/llm/narrate.ts`
**Envelope:** `@anthropic-ai/sdk` against `env.LLM_BASE_URL` (`api.z.ai/api/anthropic`), Anthropic
Messages shape, `maxRetries: 0` because the module does its own budgeted single repair.
**Budgets, measured:** session 25 s primary / 18 s repair / 45 s overall / 1200 max tokens. Fifteen
live `glm-5.3` calls on 2026-08-21 took 10.2–16.4 s, clustering at 13–16 s.
**Contract:** primary call → Zod → one repair → **silence**. Nothing in the file throws for an LLM
problem, and there is deliberately no canned-prose fallback: "the only safe fallback for prose is
the absence of prose."
**Output shape:** a forced `report` tool call, validated by `InsightPayloadSchema`.

### Entry Point: `GET /api/cron/rollup` (nightly, 20:00 UTC)

Guarded by `CRON_SECRET`. Walks `listActiveUserIds`, sweeps period badges first because it is the
cheap half, then generates week and month insights. Sequential on purpose, every user in its own
`try`, and it checks a soft deadline before starting each unit so it stops itself before the
platform's 60 s ceiling kills it mid-call. **R3's trigger evaluation follows this shape exactly.**

### Data Persistence

**Database:** Neon Postgres via `@neondatabase/serverless`, Drizzle ORM, whole schema in
`lib/db/schema.ts`. Two schema-wide rules:

- **Integers in the smallest sensible unit** — distance in metres, duration and pace in seconds.
  `profiles.weight_kg` is the single deliberate exception. Floats summed over a month drift.
- **`runs.reviewed_at IS NOT NULL` gates every aggregate**, enforced in `lib/db/queries.ts` and
  asserted by `tests/db.queries.reviewedOnly.test.ts`.

**Blob:** Vercel Blob, `shots/` prefix, `BLOB_READ_WRITE_TOKEN`.
**Cache:** none beyond `insights.facts_hash` (sha256 of the facts; same facts, no call).

### Exit Points

Server Components render from stored rows; Server Actions mutate and `revalidatePath`; the four
sanctioned route handlers are `/api/extract`, `/api/upload`, `/api/auth/[...nextauth]` and
`/api/cron/*` (D7).

**`NEXT_PUBLIC_` is forbidden outright.** `scripts/check-client-secret-boundary.mjs` RULE 3 greps
`app/`, `lib/` and `components/` for the prefix and fails unconditionally. Next's own PWA guide
reads the VAPID public key as `process.env.NEXT_PUBLIC_VAPID_PUBLIC_KEY` in a client component.
**The guide is not followed on this point.** The key is read server-side and passed to the client
component as a prop, which is functionally identical — the value ends up in the browser either
way — and leaves RULE 3 intact. This is the one place where a documented invariant collides with
the new feature and does **not** need repealing.
