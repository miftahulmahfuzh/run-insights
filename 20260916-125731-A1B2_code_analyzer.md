## Detailed Requirements Understanding

**Problem/Requirement Statement**: Nina's selfies (`kind = 'generated'` rows in
`nina_message_images`, rendered from `lib/nina/imagegen.ts`'s `buildNinaImagePrompt`) visually
skew toward (1) an arm's-length "phone selfie" composition the user dislikes, (2) a head that
reads oversized relative to the body, and (3) calves/feet that read short or small even though
the operator has `focus_calves` turned on. The user accepts these may partly be limits of
`qwen/qwen-image-3-pro` itself, but wants the prompt text tuned as far as it reasonably can go
before accepting the model's ceiling.

**Success Criteria**: The prompt text built by `buildNinaImagePrompt` for `purpose: 'selfie'`
(the path every one of the six sampled photographs went through) explicitly and unambiguously
instructs against arm's-length/mirror selfie framing, states a natural, undistorted head-to-body
proportion, and describes calves and feet as long, fully visible and in proportion — using the
one mechanism this API actually has (everything rides in the single `prompt` string; see
"No negative-prompt parameter" below) — without breaking any existing `tests/nina.imagerecipe.test.ts`
assertion that is unrelated to the three problems.

**Key Considerations / Constraints**:
- No source-of-truth divergence: the six sampled photographs, `nina_image_prefs.prompt_template`
  (the operator's live override) and `NINA_PROMPT_TEMPLATE_DEFAULT` (the shipped default) are
  **byte-identical** for this user today — see "Current Prompt" below. There is no live A/B to
  reconcile; the fix is a single edit.
- **No `negative_prompt` API field exists in this codebase's OpenRouter call.**
  `buildImageRequestBody` (`lib/nina/imagerecipe.ts:535-561`) sends only
  `model, prompt, resolution, aspect_ratio, n, seed, input_references` — nothing named
  `negative_prompt` has ever been used or documented anywhere in this repo. The established,
  proven convention (visible in the shipped `NINA_SELFIE_STYLE` string itself: `"no studio
  lighting, no retouching, no text, no watermark, no logo, no border"`) is to write negatives
  **inline, in the positive prompt**, as "no X" clauses. This analysis follows that convention
  rather than inventing an unverified API parameter.
- `GENERATE_IMAGE_TOOL.description` (`lib/nina/prompts/tools.ts:275-300`) says `"Take a photo of
  yourself and send it."` to the chat model that decides *when* to call the tool and writes its
  `scene`/`mood` arguments — but that description string is **never concatenated into the actual
  image prompt** (`buildNinaImagePrompt` only reads `input.scene`, `input.mood`, `tuning`,
  `prefs`). The six sampled `scene` values are all written in the third person ("She dances...",
  "She sits at a wooden table...", "She is cooking rendang...") — none instructs a
  first-person/selfie composition. The selfie bias is therefore attributable to the **camera-style
  block itself** (`NINA_SELFIE_STYLE`), not to the tool description, and the fix stays inside
  `lib/nina/imagegen.ts`.
- **The FOCUS mechanism's per-key elaboration sentence is dead code for `calves` on both paths.**
  `ninaFocusBlock` (which is the only caller of `NINA_FOCUS_EMPHASIS[key].sentence`) is used
  **only** on the avatar path, and `calves` is excluded from `NINA_AVATAR_FOCUS_KEYS = ['face',
  'skin']`. On the selfie path, the template's static `FOCUS:` line reads only `joinTerms(...)`
  over each key's `.term` — `ninaFocusBlock`/`.sentence` is never called at all
  (`tests/nina.imagerecipe.test.ts:593-623` pins this: *"the rung sentences are gone from
  selfies"*). So `NINA_FOCUS_EMPHASIS.calves.sentence` — *"Her very long calves run most of the
  length of the frame, full and sharply defined all the way down to a narrow ankle."* — is
  **written in the source but never sent to the model, on any path, at any setting.** The only
  lever the FOCUS mechanism gives a selfie prompt is `calves.term` itself (currently the six words
  `'her very long calves'`), which is the one place worth spending the fix.
- The live prefs row for the sampled account has `prompt_length = 50` → `ninaBand(50).index = 2`
  → band `'mid'`. This only matters for the **avatar** path and for whether `POSE AND PRESENCE`
  appears; it does **not** gate anything about calves on the selfie path (previous point).

## Current Dataflow

### Entry Point: `buildNinaImagePrompt` (`lib/nina/imagegen.ts:567`)

**Trigger:** called from the image job dispatcher when Nina's `generate_image` tool fires
(`purpose: 'selfie'`), and from `/admin/image-generation`'s preview/test button.
**Input:** `{ purpose, scene, mood?, tuning?, prefs? }`.
**Validation:** none inline; `effectiveNinaImageTemplate` falls back to the shipped default if
the stored `prefs.promptTemplate` fails `validateNinaImageTemplate`.
**Next step:** the returned string becomes `body.prompt` in `buildImageRequestBody`
(`lib/nina/imagerecipe.ts:549`), POSTed to `https://openrouter.ai/api/v1/images/generations`.

### Processing Chain (selfie path)

1. `ninaPromptRung(prefs.promptLength)` resolves a rung — used for `bodySentences`, `face`,
   `outfit`, `presence`, `camera` on the **avatar** path only; the selfie path ignores
   `rung.focus` entirely (see Key Considerations).
2. `effectiveNinaImageTemplate(prefs)` resolves to either the stored `prefs.promptTemplate` or
   `NINA_PROMPT_TEMPLATE_DEFAULT` — today, byte-identical for the sampled account (verified: both
   are the same 1234-character string).
3. `blocks` is assembled: `wardrobe`, `focus` (= `joinTerms` over selected `NINA_FOCUS_EMPHASIS[key].term`),
   `presence` (= `ninaPhotoPresence`, only non-empty when `steamy`/`flirty` are band `high`+),
   `venue`, `time`, `scene`, `mood`, `notes`.
4. `renderNinaImagePrompt(template, blocks)` substitutes tokens, drops any line whose only token
   expanded to `''`, collapses blank runs, trims.

### Exit Point

The rendered string is stored verbatim in `nina_message_images.prompt` (via `sidecarText`) and
sent as `body.prompt` to OpenRouter. No transformation happens between "what this file returns"
and "what the model receives" — this file's output **is** the whole instruction the model sees for
that call, aside from the seed and (when set) a reference image.

## Key Data Structures

### `NINA_SELFIE_STYLE` (`lib/nina/imagegen.ts:82`)

```
A DSLR photograph, as if taken and sent in a chat app. Natural daylight, slightly imperfect
framing, shallow depth of field, visible skin texture, no studio lighting, no retouching, no
text, no watermark, no logo, no border. Realistic photograph, not an illustration and not a
render.
```

Says nothing about who is holding the camera. "DSLR photograph" and "sent in a chat app" pull in
opposite directions — a DSLR is not the device someone snaps a chat photo on — and the ambiguity
resolves, in the sampled output, toward a phone-in-hand, arm-extended selfie composition (visible
in 4 of the 6 sampled images — see Impact Points).

### `NINA_FOCUS_EMPHASIS.calves` (`lib/nina/imagegen.ts:333-336`)

```ts
calves: Object.freeze({
  term: 'her very long calves',
  sentence: `Her very long calves run most of the length of the frame, full and sharply defined all the way down to a narrow ankle.`,
}),
```

`term` is the only part of this record that ever reaches a selfie prompt (see Key Considerations).
It renders today as: `FOCUS: Emphasise her very long calves above everything else in this
photograph.` — confirmed verbatim in 5 of the 6 sampled prompts (position 21's prompt was not
recorded).

### `NINA_PROMPT_TEMPLATE_DEFAULT` (`lib/nina/imagegen.ts:431-455`)

The full shell (camera → `SUBJECT:` → outfit → `FOCUS:` → `POSE AND PRESENCE:` → `VENUE:` →
`TIME:` → `SCENE:` → `EXPRESSION AND ENERGY:` → `NOTES:`). No block in this shell addresses
camera distance, lens choice, or head-to-body proportion.
