## Goal

After this phase, an admin opening any full-view Nina photograph in the **client** app — the chat
overlay, `/nina/about` → Foto profil, `/nina/about` → Media, or `/photo/[kind]/[id]` — sees phase
3's icon-only copy-admin-link button in the viewer header, beside the close ✕ and (where it already
exists) beside the "Buka detail job foto ini" link. For every other signed-in user, and for
`/photo/shot/<id>`, the header is exactly what ships today — not because a render-time `if` hides a
control, but because the server never sent an origin to build one with. `/nina`, `/nina/about` and
`/photo/**` keep rendering where `ADMIN_EMAILS` is unset, which is every preview deployment and
every plain local run.

## Implementation Steps

### Step 1: The R4 gate — one `server-only` resolver

**File:** `lib/admin/adminLinkOrigin.ts` (new)
**Change:** The whole gate, in one function, with the measured hazard written down beside it.

**Why it may not simply call `getAdminIdentity()`** (plan invariant 7, measured, not hypothetical):
`isAdminEmail` (`lib/env.ts:261`) returns `false` early for a null/empty email, but for a real one
it reaches `adminEnv()` → `load('admin', adminSchema)` (`lib/env.ts:202-205`, `:241-250`), and
`load` calls `fail()` — a **thrown** `Error` — when `safeParse` rejects. `adminSchema` is
`{ ADMIN_EMAILS: nonEmpty('ADMIN_EMAILS') }` and `nonEmpty` is `z.string().min(1)` (`lib/env.ts:34`),
so *unset* and *empty* both throw. `ADMIN_EMAILS` is Production-scope only in Vercel and is **absent
from this repo's `.env.local`** (verified: `grep -c ADMIN_EMAILS .env.local` → 0). A bare
`getAdminIdentity()` on `/nina` would therefore 500 for every **signed-in** user on every preview
deployment and in any plain local run — taking down the chat screen in order to hide a button.

**Why a presence probe and not a `try`/`catch`.** A `try`/`catch` around `getAdminIdentity()` would
also swallow an `auth()` failure — a corrupt session cookie, a decryption error, an Auth.js
misconfiguration — and answer "not an admin" to a problem that is not about admin-ness at all. So
the check is a *precondition*, evaluated before the call, on exactly the condition that makes
`adminEnv()` throw and on nothing else. There is no `try`/`catch` anywhere in this module, and an
`auth()` failure propagates here exactly as it does in `requireUserId()`.

**Why `process.env.ADMIN_EMAILS` is read raw here.** It is a **presence probe, never a value read**:
the string is not split, not lowercased, not compared to anything, and the admin verdict still comes
from `isAdminEmail` inside `getAdminIdentity`. `lib/env.ts` stays the one place the list is parsed
and the one place the predicate lives, which is what plan invariant 6 is about. `ADMIN_EMAILS` is
**not** on `scripts/check-client-secret-boundary.mjs`'s `SECRETS` list, so RULE 2 does not fire; the
exemption is not needed and must not be added.

**Code:**

```ts
import 'server-only'

import { getAdminIdentity } from '@/lib/admin/requireAdmin'
import { shareOrigin } from '@/lib/share/origin'

/**
 * **R4's whole gate: the origin an admin may mint a `/admin/nina` link from, or `null`.**
 *
 * The three client entry points onto a full-view Nina photograph — `/nina`, `/nina/about` and
 * `/photo/[kind]/[id]` — call this beside the reads they already run and thread the answer down as
 * ONE nullable prop. `null` is not "render the button disabled": it is "there is no origin, so
 * there is nothing to render and nothing was sent". A non-admin's RSC payload therefore carries no
 * admin origin at all, which makes hiding the control structural rather than a render-time `if`
 * over a value that shipped anyway (plan invariant 6).
 *
 * ── ONE NULLABLE PROP, NOT AN `isAdmin` BOOLEAN BESIDE AN ALWAYS-SENT ORIGIN ──────────────────
 * The button needs both facts, and two props that must agree are two props that will one day
 * disagree. Collapsing them also removes the only way to get R4 subtly wrong: there is no state in
 * which the origin is present and the verdict says no.
 *
 * ── WHY `getAdminIdentity()` IS NOT CALLED UNCONDITIONALLY (MEASURED — PLAN INVARIANT 7) ──────
 * `getAdminIdentity` → `isAdminEmail` (`lib/env.ts:261`) → `adminEnv()` → `load('admin', …)`,
 * which `fail()`s with a THROWN Error when `ADMIN_EMAILS` is missing or empty (`lib/env.ts:183-205`,
 * and `nonEmpty` is `z.string().min(1)` at `:34`). `isAdminEmail`'s early `email == null` return
 * means a signed-OUT visitor never reaches that; a signed-IN one does. `ADMIN_EMAILS` is
 * Production-scope only in Vercel and is absent from this repo's `.env.local`, so an unguarded call
 * here would 500 the chat screen for every signed-in user on every preview deployment and in every
 * plain local run. Hiding a button is never worth taking the screen down.
 *
 * ── WHY A PRESENCE PROBE AND NOT A try/catch ─────────────────────────────────────────────────
 * A `catch` around the call would also swallow an `auth()` failure — a corrupt session cookie, a
 * decryption error — and answer "not an admin" to a question that was never about admin-ness. So
 * the guard is a PRECONDITION on exactly the condition that makes the lazy group throw, and
 * nothing else; there is no `try`/`catch` in this module, and an auth failure propagates from here
 * exactly as it does from `requireUserId()`.
 *
 * The raw read below is a PRESENCE PROBE and never a value read: the string is not split, not
 * lowercased, and never compared to an address. `lib/env.ts` remains the only parser of the list
 * and `isAdminEmail` the only predicate — the admin address is not written in this repo's source
 * and must not be (`lib/env.ts:149`: "it is a personal address"). `ADMIN_EMAILS` is deliberately
 * not on `scripts/check-client-secret-boundary.mjs`'s secret list, so this read needs no exemption.
 *
 * ── `shareOrigin()` CANNOT BE THE NEW THROW ──────────────────────────────────────────────────
 * It reads `authEnv().AUTH_URL`, and `AUTH_URL` is `.optional()` (`lib/env.ts:82-85`); the group's
 * three required keys are the ones `auth()` itself already needed to produce the identity this
 * function just received. So by the time this line runs, that group has already loaded. And it is
 * `shareOrigin()` rather than `window.location.origin` on purpose: this link is pasted into
 * WhatsApp and opened on a desktop later, and a preview deployment's hostname dies at the next
 * push (repo invariant 9; `lib/share/origin.ts`'s own header carries the argument).
 */
export async function resolveAdminLinkOrigin(): Promise<string | null> {
  const configured = process.env.ADMIN_EMAILS
  if (configured == null || configured.length === 0) return null

  const identity = await getAdminIdentity()
  if (identity === null) return null

  return shareOrigin()
}
```

**Impact:** One new `server-only` module with one export and three call sites. No database read, no
new env variable, no change to how admin-ness is decided. On a preview deployment or an
`ADMIN_EMAILS`-less local run it short-circuits before `auth()` is called a second time, so those
pages pay nothing at all.

   * the copy-admin-link button in the viewer header mints its URL from (2026-10-01, R1/R3).

**Code (replace `chatSessionPhotos`'s loop body, `:182-197` — the whole function for clarity):**

```ts
export function chatSessionPhotos(
  messages:
    | readonly {
        id: string
        imageUrls?: readonly string[] | null
        imageIds?: readonly string[] | null
        imageKinds?: readonly string[] | null
        turnId?: string | null
      }[]
    | null
    | undefined,
): ChatSessionPhoto[] {
  if (messages == null) return []
  const flat: ChatSessionPhoto[] = []
  for (const message of messages) {
    const photos = chatViewerPhotos(message)
    for (let index = 0; index < photos.length; index += 1) {
      const attachId = attachableIdAt(message.imageIds, index)
      flat.push({
        ...photos[index]!,
        messageId: message.id,
        indexWithinMessage: index,
        attachId,
        /* Spread rather than `rowPointer: attachId === null ? undefined : …`, because
         * `Object.keys` counts a key whose value is `undefined` and the optimistic row must carry
         * no handle at all — "absent renders nothing" is a claim about the KEY, and
         * `chatphotos.test.ts` asserts the exact key set. */
        ...(attachId === null ? {} : { rowPointer: { kind: 'image' as const, id: attachId } }),
      })
    }
  }
  return flat
}
```

- **`components/nina/usePhotoViewer.ts` turned out not to need threading** — the hook returns the

  files for this phase and no longer names `usePhotoViewer.ts`.
- **Docs.** `docs/architecture.md` and `CHANGELOG.md` describe the four overlays and the admin

  any one phase, and are deliberately not touched here.
- **Drive-by not taken:** `galleryViewer` maps `viewerLists.chat` while the grid maps `galleryItems`

## Rollback

`git revert` the phase's commit. Every change is additive:

- the four overlays return to the headers they ship today, and the job-detail link on two of them
  is restored by the same revert;
- `ChatSessionPhoto` loses one optional field, which nothing else reads;
- `lib/admin/adminLinkOrigin.ts` is deleted with its only three callers in the same commit, so no
  dangling import survives;
- the three pages stop calling `resolveAdminLinkOrigin()`, which means one fewer `auth()` call and
  no behaviour change for anyone.

**Nothing in this phase writes.** No migration, no schema change, no database write, no blob write,
no Vercel env edit — the repo has exactly one database and `.env.local`'s `DATABASE_URL` is
production, which is precisely why there is nothing here to unwind. Reverting phase 4 alone leaves
phases 1–3 intact and inert: phase 1's minter and phase 3's button simply have no mount points
again, and phase 2's `/admin/nina` deep link keeps working for any link already pasted somewhere.
